# Local development and build checks

Use Node.js 24 or later (the Lambda build targets Node 24), npm, and pnpm 11.18.0. The existing workspace uses pnpm `workspace:` and `catalog:` dependencies, so npm is an entry point that delegates workspace installation to pnpm. `pnpm-lock.yaml` remains authoritative.

```sh
npm install -g pnpm@11.18.0
cp .env.example .env
npm install
npm run build
```

All template values are blank. Local commands ignore blank values and provide only non-production defaults where necessary. `npm run build` uses port 5173 and base path `/` for Vite. It typechecks and builds the existing workspace. The normal prerender step reads the public live API using no keys, so it needs network access and a working API. The Vercel build command in `vercel.json` is unchanged.

For a deterministic check with no live data, run:

```sh
npm run build:sample
```

This starts a temporary loopback fixture API, converts the ten fictional DynamoDB examples with the real `normalizeOpportunity` function, and runs the same workspace build through the existing `PRERENDER_API_BASE` setting. Publication is overridden only in memory for this fixture. **Do not deploy the sample build output.** A normal build overwrites it.

## API startup without service keys

After building:

```sh
npm run start:example
# in another terminal:
curl http://localhost:8080/api/healthz
```

The local launcher generates a temporary session secret, supplies `postgresql://localhost:5432/nextstep`, sets port 8080, and starts the unchanged Express entry point. It does not create a database or fake application data. Health is expected to return `{"status":"ok"}`; database, matching, admin and discovery requests require their respective configuration. This launcher refuses `NODE_ENV=production`.

For the website dev server, use a separate terminal:

```sh
npm run dev:website
```

Vite proxies `/api` to localhost:8080. Without configured data services, data-dependent pages will not populate.

## Service configuration

Fill only the `.env` values needed for your workflow; never commit that file. Blank optional values are omitted by the local launcher. For scripts that load `.env` directly, remove unused blank optional entries so the source's `??` defaults apply.

| Variables | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection for legacy opportunities, candidates and server sessions |
| `SESSION_SECRET` | Strong private session signing value for a persistent server; locally generated by `start:example` |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Admin login; source defaults username to `admin`, requires configured password |
| `CANDIDATE_API_TOKEN` | Authenticates external candidate ingestion |
| `AWS_REGION`, `AWS_S3_BUCKET`, `DYNAMODB_TABLE` | Storage names/region for the AWS helper |
| `AWS_PROFILE` or `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` | Standard AWS SDK credential chain; prefer IAM roles in AWS |
| `EXA_API_KEY` | Opportunity search in the Lambda/research functions |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` | AI matching/extraction; base URL typically `https://api.deepseek.com`; inspect source defaults |
| `YOUTUBE_API_KEY`, `YOUTUBE_RUN_ID` | Video discovery API and optional archive run identifier |
| `SEARCH_CONCURRENCY`, `EXTRACT_CONCURRENCY`, `TARGET_VALID_DISCOVERIES`, `MAX_DISCOVERY_PASSES`, `MAX_EXTRACTIONS_PER_RUN`, `RUN_BUDGET_MS` | Optional Lambda limits; omit to use source defaults |
| `PORT`, `BASE_PATH`, `NODE_ENV`, `LOG_LEVEL` | Local server/build configuration |
| `SITE_URL`, `VITE_SITE_URL`, `PRERENDER_API_BASE` | Sitemap/SEO origin and build-time API override; Vite variables are public |
| `SHOW_PENDING_OPPORTUNITIES` | Development visibility option; disabled in production by source logic |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEARCH_TRIGGER_SECRET` | Separate Supabase edge functions; not needed for the Vercel API startup |
| `ALLOW_ECDATABASE_IMPORT` | Explicit opt-in for the historical import tool |
| `API_BASE` | API target for integration tests |
| `REPL_ID` | Replit development tooling only |

Vite provides `import.meta.env.BASE_URL` and `DEV`; these are built-in values, not secrets to put in `.env`. The template also includes standard AWS SDK credential variables, even though the app intentionally does not read them directly.

## iPhone

Clone [Paoloop6/nextstepdatabase](https://github.com/Paoloop6/nextstepdatabase), open `nextstepdatabase.xcodeproj` in Xcode 26.6 or later, and choose an iPhone simulator. The current deployment target is iOS 26.5. The app requires no embedded API keys; it calls the public backend over HTTPS. Device installation needs your own Apple signing team.

```sh
xcodebuild -project nextstepdatabase.xcodeproj -scheme nextstepdatabase \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

## Checks that write to services

`test:aws-storage`, `test:opportunities`, import/anonymization scripts, Lambda invoke/deploy and video sync are integration/maintenance commands. Some write or delete records in the configured services. They are not part of the keyless build check and should only target an isolated development environment.
